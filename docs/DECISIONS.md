# DECISIONS.md — لاگ تصمیم‌ها

## چطور از این فایل استفاده کنیم

- هر تصمیم مهم (معماری، ابزار، قرارداد با بک‌اند، طراحی) یک ورودی جدید می‌گیرد.
- ورودی‌های قدیمی حذف نمی‌شوند. اگر تصمیمی عوض شد، ورودی جدید می‌نویسیم و وضعیت قدیمی را «جایگزین‌شده با D-0XX» می‌کنیم.
- وضعیت‌ها: `پیشنهادی` (هنوز تأیید نشده) | `تأییدشده` | `جایگزین‌شده`
- هر ورودی جدید داخل یک PR (یا همراه کامیتی با پیشوند `docs:`) ثبت شود.

### قالب

```
## D-0XX — عنوان کوتاه
- تاریخ:
- وضعیت:
- تصمیم:
- دلیل:
- جایگزین‌هایی که بررسی شد:
- پیامد / ریسک:
```

## D-003 — شروع با یک اپ، نه monorepo

- تاریخ: 2026-10-27
- وضعیت: پیشنهادی
- تصمیم: یک پروژه‌ی Next.js با مرزهای مشخص (`components/ui`, `features/*`). وقتی پروژه‌ی فروشگاهی دوم شروع شد، `ui` و بخش‌های عمومی `features` را به پکیج جدا استخراج می‌کنیم.
- دلیل: monorepo از روز اول، پیچیدگی ابزار اضافه می‌کند و قبل از دیدن نیاز واقعیِ پروژه‌ی دوم، مرز پکیج را حدسی می‌زنیم.
- جایگزین: Turborepo + pnpm workspaces از ابتدا.
- ریسک: اگر مرزها رعایت نشوند، استخراج بعدی سخت می‌شود. قاعده‌ی «ui هیچ چیز خاص این پروژه را import نمی‌کند» با ESLint اجباری شود.
