# PROJECT.md — فروشگاه آنلاین کفش (ریپوی فرانت‌اند)

> این فایل «حافظه‌ی پروژه» است. هر چت جدید با هوش مصنوعی را با چسباندن این فایل (و بخش‌های مرتبط `DECISIONS.md`) شروع کنید.
> مواردی که با ☐ مشخص شده‌اند هنوز تصمیم نهایی نشده‌اند. وقتی تصمیم گرفتید، آن‌ها را در `DECISIONS.md` ثبت و اینجا به‌روزرسانی کنید.

## ۱. خلاصه

- فروشگاه آنلاین کفش، فارسی و راست‌به‌چپ (RTL)، کاملاً ریسپانسیو (موبایل‌اول).
- هدف دوم: ساخت زیرساختی از کامپوننت‌ها و منطق فروشگاهی که در پروژه‌های بعدیِ فروشگاهی دوباره استفاده شود.
- نام برند: ✅ کفش بهنام
- دامنه: ☐

## ۲. تیم و مسئولیت‌ها

| نقش        | مسئولیت                                                        |
| ---------- | -------------------------------------------------------------- |
| Siavash    | فرانت‌اند (این ریپو)، نظارت بر طراحی                           |
| همکار      | بک‌اند NestJS (ریپوی جدا)، تعریف و نگهداری API                 |
| هوش مصنوعی | پیشنهاد طراحی و معماری، تولید کد، بازبینی (تصمیم نهایی با تیم) |

ریپوی فرانت و بک‌اند جدا هستند. نقطه‌ی هماهنگی بین دو ریپو **قرارداد API (OpenAPI/Swagger)** است.

## ۳. استک فرانت‌اند (پیشنهادی؛ جزئیات در `DECISIONS.md`)

- Next.js (App Router) + TypeScript (حالت strict)
- Tailwind CSS، با design tokens مشترک
- مدیریت state:
  - داده‌ی سرور: TanStack Query
  - state سمت کاربر (مثل سبد خرید): Zustand
- فرم‌ها: React Hook Form + Zod
- API client: تایپ‌ها از OpenAPI بک‌اند تولید می‌شوند (`openapi-typescript`)
- داده‌ی ساختگی تا آماده شدن API: MSW
- کیفیت: ESLint، Prettier، Vitest + Testing Library، Playwright (برای جریان خرید)، Storybook برای کامپوننت‌ها
- مدیر بسته: pnpm

## ۴. صفحات و قابلیت‌ها

### عمومی (مشتری)

- خوش‌آمدگویی (onboarding)
- لندینگ: navbar، hero، دسته‌بندی‌ها، پرفروش‌ها، تازه‌ها، برندها، مزایا (ارسال، بازگشت کالا)، نظرات، خبرنامه، footer
- لیست محصولات با فیلتر و مرتب‌سازی، جستجو
- صفحه‌ی محصول: گالری، رنگ، سایز، راهنمای سایز، موجودی، افزودن به سبد، علاقه‌مندی
- سبد خرید
- Checkout: اطلاعات تماس، آدرس، ارسال، پرداخت
- ورود / ثبت‌نام

### داشبورد کاربر

- خلاصه، سفارش‌ها (و جزئیات/پیگیری)، آدرس‌ها، علاقه‌مندی‌ها، ویرایش پروفایل، امنیت حساب

### داشبورد ادمین

- نمای کلی (فروش، سفارش‌های جدید)، مدیریت محصولات (تنوع رنگ/سایز/موجودی)، دسته‌بندی و برندها، سفارش‌ها و تغییر وضعیت، کاربران، تخفیف‌ها، تنظیمات سایت

> ☐ تقویم شمسی؟ ☐ درگاه پرداخت (کدام؟) ☐ حالت روشن/تیره یا فقط تیره؟ ☐ کد تخفیف و نقد/امتیاز در فاز اول؟

## ۵. اصول معماری فرانت (خلاصه؛ جزئیات در `docs/FRONTEND_STRUCTURE.md`)

1. **لایه‌بندی برای قابل استفاده‌ی مجدد:** `components/ui` (عمومی، بدون منطق فروشگاه) ← `features/*` (منطق فروشگاهی) ← `app/*` (فقط چینش صفحه).
2. هیچ نام برند، رنگ یا متن خاص این پروژه داخل `components/ui` نیاید. همه از tokens و props.
3. RTL از روز اول: فقط logical properties (`ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`).
4. تمام ارتباط با API فقط از `lib/api` و `features/*/api` انجام شود، نه مستقیم داخل کامپوننت.
5. هر مقدار قابل نمایش پول، عدد و تاریخ از توابع مرکزی (`formatPrice`, `toPersianDigits`) عبور کند.
6. **امنیت:** محافظت صفحات در فرانت فقط برای تجربه‌ی کاربر است. احراز هویت و سطح دسترسی (کاربر/ادمین) را بک‌اند اعمال می‌کند. توکن‌ها در `localStorage` ذخیره نشوند (پیشنهاد: کوکی `httpOnly`، هماهنگ با بک‌اند).

## ۶. طراحی

- مرجع سبک: `STYLE_GUIDE.md` (رنگ‌ها، تایپوگرافی، فاصله‌ها، کامپوننت‌ها)
- فایل Figma: ☐ لینک (بعد از ساخت اینجا قرار می‌گیرد)
- نقاط شکست (breakpoints): موبایل ۳۹۰، تبلت ۷۶۸، لپ‌تاپ ۱۲۸۰، دسکتاپ ۱۴۴۰
- لوگو و تصاویر محصول باید مال خود پروژه باشند، نه تصاویر برندهای دیگر.

## ۷. ارتباط با بک‌اند (NestJS)

- بک‌اند با `@nestjs/swagger` فایل OpenAPI تولید می‌کند (معمولاً در مسیر `/api-json`).
- فرانت با یک اسکریپت (`pnpm api:gen`) از روی آن تایپ‌ها را تولید می‌کند. هر تغییر API = یک بار اجرای اسکریپت + رفع خطاهای TypeScript.
- تا آماده شدن endpointها، با MSW و داده‌ی ساختگیِ هم‌شکل با قرارداد جلو می‌رویم تا موازی کار کنیم.
- قواعد مشترک که باید با همکار نهایی شوند: ☐ ساختار خطاها ☐ pagination ☐ احراز هویت (کوکی/توکن) ☐ آپلود تصویر ☐ واحد پول (تومان/ریال، عدد صحیح)
