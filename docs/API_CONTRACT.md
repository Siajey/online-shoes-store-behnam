# API_CONTRACT.md — قرارداد فرانت و بک‌اند

> این‌ها **پیشنهاد اولیه** هستند. در جلسه‌ی مشترک هر مورد را تأیید یا اصلاح کنید و بعد وضعیت را از ☐ به ✅ ببرید، و تصمیم را در `DECISIONS.md` ثبت کنید.
> منبع حقیقت برای شکل دقیق درخواست/پاسخ: **Swagger (OpenAPI)** بک‌اند. این فایل فقط قواعد مشترک را می‌گوید.

| #   | موضوع                             | پیشنهاد                                                                                                                          | وضعیت     |
| --- | --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | --------- |
| 1   | آدرس Swagger JSON                 | `https://<staging>/api-json` ثابت و همیشه به‌روز                                                                                 | ☐         |
| 2   | پیشوند و نسخه                     | `/api/v1/...`                                                                                                                    | ☐         |
| 3   | قالب JSON                         | `camelCase` برای کلیدها                                                                                                          | ☐         |
| 4   | **واحد پول**                      | عدد صحیح، به **تومان** (یا ریال؟). هرگز float                                                                                    | ☐ (D-011) |
| 5   | تاریخ و زمان                      | ISO 8601 در UTC (`2026-10-27T10:20:00Z`)؛ تبدیل به شمسی فقط در فرانت                                                             | ☐         |
| 6   | شناسه‌ها                          | رشته (UUID) یا عدد؟ همه‌ی مدل‌ها یکسان                                                                                           | ☐         |
| 7   | ساختار خطا                        | `{ "statusCode": 400, "code": "VALIDATION_ERROR", "message": "…فارسی برای کاربر…", "fields": { "phone": "شماره نامعتبر است" } }` | ☐         |
| 8   | Pagination                        | `?page=1&limit=12` → `{ "items": [], "total": 128, "page": 1, "limit": 12 }`                                                     | ☐         |
| 9   | فیلتر و مرتب‌سازی محصولات         | `?category=&sizes=40,41&colors=&minPrice=&maxPrice=&sort=newest\|price_asc\|price_desc`                                          | ☐         |
| 10  | **احراز هویت**                    | ورود با OTP موبایل؛ توکن در کوکی `httpOnly` + `Secure` + `SameSite=Lax`؛ مسیر refresh؛ CSRF چطور؟                                | ☐ (D-008) |
| 11  | نقش‌ها                            | `user` و `admin`؛ بک‌اند در **هر** endpoint ادمین بررسی می‌کند (فرانت فقط مسیر را مخفی می‌کند)                                   | ☐         |
| 12  | آپلود تصویر                       | `POST /uploads` → `{ url }`؛ حداکثر حجم و فرمت‌ها                                                                                | ☐         |
| 13  | CORS                              | دامنه‌ی فرانت (local و staging) در allow-list، `credentials: true`                                                               | ☐         |
| 14  | سبد خرید                          | مهمان: سمت فرانت (localStorage)؛ بعد از ورود: ادغام با سبد سرور؟                                                                 | ☐         |
| 15  | پرداخت                            | کدام درگاه؟ جریان: `POST /orders` → آدرس درگاه → بازگشت به `/payment/callback` → تأیید سمت **بک‌اند**                            | ☐         |
| 16  | محدودیت نرخ (rate limit) برای OTP | مثلاً ۵ درخواست در ۱۰ دقیقه برای هر شماره                                                                                        | ☐         |

## چک‌لیست قبل از اتصال هر endpoint

- [ ] در Swagger هست و نمونه‌ی پاسخ دارد
- [ ] خطاهای ممکن (۴۰۰/۴۰۱/۴۰۳/۴۰۴/۴۰۹) مستند شده‌اند
- [ ] `pnpm api:gen` تایپ‌ها را ساخت و `typecheck` سبز است
- [ ] handler ساختگی (MSW) همان endpoint حذف یا خاموش شد
