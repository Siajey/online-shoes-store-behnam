# قرارداد پیشنهادی API نظرات

فرانت فیچر نظرات را با داده‌ی موقت ساخته است (`src/features/reviews`). این سند می‌گوید بک‌اند چه چیزی بسازد تا فرانت فقط یک فایل (gateway) را عوض کند. همه‌ی مسیرها با پیشوند `/api/v1` و قالب پاسخ مشترک پروژه (بخش ۲ و ۳ فایل `API_CONTRACT.md`) هستند.

## مدل نظر (آنچه فرانت لازم دارد)

| فیلد               | نوع             | توضیح                                                           |
| ------------------ | --------------- | --------------------------------------------------------------- |
| `id`               | رشته            | شناسه‌ی نظر                                                     |
| `productId`        | رشته            | شناسه‌ی کالا                                                    |
| `authorName`       | رشته            | نام نمایشی با حفظ حریم خصوصی، مثل «سارا م.» (نه شماره‌ی موبایل) |
| `rating`           | عدد صحیح ۱ تا ۵ | امتیاز                                                          |
| `title`            | رشته یا null    | حداکثر ۸۰ نویسه                                                 |
| `body`             | رشته            | بین ۱۰ تا ۱۰۰۰ نویسه                                            |
| `createdAt`        | ISO 8601        | زمان ثبت                                                        |
| `verifiedPurchase` | بولی            | کاربر این کالا را خریده و سفارش تحویل شده دارد                  |

## مسیرها

### ۱. فهرست نظرهای یک کالا (عمومی)

`GET /products/:productId/reviews?pageSize=10&nextCursor=...&sort=createdAt:desc`

پاسخ: `{ items: Review[], nextCursor: string | null }` فقط نظرهای تأییدشده.

### ۲. خلاصه‌ی امتیاز یک کالا (عمومی)

`GET /products/:productId/reviews/summary`

پاسخ: `{ count: number, average: number, distribution: { "1": n, "2": n, "3": n, "4": n, "5": n } }`

میانگین و پراکندگی باید روی **همه‌ی** نظرهای تأییدشده حساب شود، نه فقط صفحه‌ی بارگذاری‌شده. (فرانت فعلی چون همه‌ی نظرها را یک‌جا دارد، خودش حساب می‌کند؛ با صفحه‌بندی واقعی از این مسیر می‌گیرد.)

### ۳. ثبت نظر (نیازمند ورود و CSRF)

`POST /products/:productId/reviews`

بدنه: `{ "rating": 5, "title": "اختیاری", "body": "متن نظر" }`

پاسخ موفق ۲۰۱ با خود نظر. خطاها:

- ۴۰۱: وارد نشده
- ۴۰۹: کاربر قبلاً برای همین کالا نظر ثبت کرده (هر کاربر یک نظر برای هر کالا؛ پیام فارسی قابل‌نمایش بدهید)
- ۴۰۴: کالا وجود ندارد
- ۴۲۲ یا ۴۰۰: اعتبارسنجی (حدود بالا)

سؤال برای مالک فروشگاه: آیا فقط خریداران اجازه‌ی نظر دارند؟ فرانت فعلاً به همه‌ی کاربران وارد‌شده اجازه می‌دهد و `verifiedPurchase` را فقط نشان می‌دهد.

### ۴. نظرهای من (نیازمند ورود)

`GET /reviews/me?pageSize=20&nextCursor=...`

مثل مسیر ۱، ولی هر آیتم علاوه بر موارد بالا `product: { id, name, slug }` دارد. نظرهای در انتظار تأیید هم برای خود نویسنده نمایش داده شود و فیلد `status` (`pending` یا `approved` یا `rejected`) داشته باشد.

## موارد اختیاری (بعداً)

- `DELETE /reviews/:id` برای حذف نظر خود کاربر.
- مدیریت نظرها در ادمین: فهرست، تأیید، رد و حذف (برای جلوگیری از اسپم و توهین، پیشنهاد می‌شود نظر جدید ابتدا در انتظار تأیید باشد).
- افزودن `rating: { average, count }` به آیتم‌های لیست و جزئیات محصول تا کارت محصول هم ستاره نشان بدهد، بدون درخواست جدا برای هر کالا.
- امکان مرتب‌سازی نظرها (تازه‌ترین، بالاترین امتیاز).

## تغییر لازم در فرانت بعد از آماده شدن

1. نوشتن `http-gateway.ts` با سه تابع `listForProduct`، `create`، `listMine` (رابط در `gateway.ts`).
2. جایگزین کردن gateway در `instance.ts` و حذف `seed.ts` و `fake-gateway.ts`.
3. افزودن `summary` به gateway و سرویس (به‌جای محاسبه‌ی محلی) و دکمه‌ی «نمایش نظرهای بیشتر» با `nextCursor`.
